# FAILURE-PATTERNS — the enforced catalogue

Patterns the agent must ACTIVELY prevent. Cite the code in commit messages and reviews; the
codes are shared vocabulary. Each row: the CODE, what happens if unchecked, the prevention,
and **the executor** — *who actually stops it.*

The executor column is the honest half of this table. Three values:

- **hook / gate** — a mechanical refusal fires (edit, spawn, commit, instrument or
  turn-boundary). The rule holds regardless of which model is reasoning.
- **generator** — a regenerated index catches it (reachability, drift, orphans) — the class
  a per-edit hook structurally cannot see.
- **judgment** — inherently un-gateable: it lives in a review, a design call, or an author's
  intent. Naming it *judgment* is a commitment to review it, not a shrug — and a row that
  could be mechanical but is not yet is a **hole**, which the coverage report prints loud.

| Code | What happens | Prevention | Executor |
|------|--------------|-----------|----------|
| **CACHE-LIE** | The agent claims a fix works by reading the file on disk, but the running system serves a cached/stale build — the change never took effect where it matters. | Verify the RUNNING system, never just the file. Reload the live process/page; confirm the new code path executed (a log line, a measured value, a behavior change) before claiming done. | judgment (+ the scripted-API verification gate) |
| **VERIFY-DISPLAY-NOT-EFFECT** | The agent verifies a control by reading its DISPLAYED value ("it shows 30") instead of the underlying EFFECT ("the variable is 30 / the pixel changed"). Display ≠ effect — a value can show but not apply. | Verify against the actual state variable or the observable effect, not the label text. "Shows the number" is not "applied." | judgment |
| **LAYOUT-DERIVED-NOT-MEASURED** | A geometry / alignment / measured value (a coordinate, a size, a cumulative offset) is COMPUTED by reading source and doing arithmetic in-head. The real value is a SUM across the whole system that no source read yields; it ships wrong. | MEASURE the value on the running system (the real rendered box / the real emitted number), derive from the measurement, apply, then RE-measure to confirm. Never compute a cumulative/observed value from source. | judgment |
| **PATCH-NOT-ESCALATED-TO-SHARED** | A bug is fixed in ONE module's copy of behavior that ≥2 modules share. The fix "works" for the patched module but leaves every sibling — and every future module — carrying the same latent bug. | Identify the SHARED home the behavior belongs to; grep EVERY sibling for the same shape FIRST. If ≥2 share it, the fix lives in the ONE shared home and the per-module copies are DELETED. The fix is at the highest shared level or it is not done. | judgment (auditor sweep; partially `helper-home`) |
| **HELPER-HAND-ROLL** | The agent builds a function / util / builder / component that a canonical helper already provides, forking the canon and losing everything the helper gives free. Language- and domain-agnostic: a re-implemented query builder, serializer, retry wrapper, or DOM component all count. | Before writing ANY reusable unit, grep the helper source + scan the generated registry (discover-then-reuse). Reuse or derive from what exists. Assembling primitives into a whole-task unit a helper already builds is the violation. | hook (grep-required + helper-home) |
| **NEW-VOCABULARY-WITHOUT-CONSENT** | The agent invents a NEW abstraction / pattern / public API / naming vocabulary when the codebase already has a canon for it — forking the vocabulary module by module (a second event-bus, a parallel error type, a rival config loader, a new naming scheme). The determinism killer: every invention makes the codebase less predictable to the next builder. | The vocabulary already exists in canon and is REUSED or DERIVED. A genuinely-new abstraction requires BOTH that it is truly new AND explicit operator consent — then it enters the canon (registry + spec) in the SAME change. Absent → STOP and ask. This is the universal, framework-agnostic core; the frontend `NEW-CLASS-WITHOUT-CONSENT` (appendix) is its CSS instance. | hook (new-surface-consent) |
| **CONSTRAINT-ARRIVES-AFTER-THE-WRITE** | Every anti-hand-roll gate adjudicates code the model has ALREADY produced. The cost is paid three ways: a refusal plus a retry on the honest cases; nothing at all on the case that matters, because an invented unit with a name nobody has used passes a NAME check every time; and an ever-growing ruleset preloaded to prevent what the gate will catch anyway — which, past the harness's output cap, is filed away undelivered while the tooling reports success. Judging output cannot make building deterministic; only bounding the input can. | Project the code registry into a CATALOG and constrain the builder to it: the agent emits a `{helper, props, children}` spec that can only name catalog entries, a validator checks it (lossless-only autofix — a fix applies only when exactly ONE candidate resolves; an invented name is never "fixed"), and a compiler emits the real calls plus an HMAC'd receipt. An edit that ADDS a new surface must be byte-contained in a fresh valid receipt. The freehand path stops being expressible, and the preloaded ruleset is replaced by a byte-capped catalog payload whose ceiling is a build failure, not a warning. | hook (spec-gate, R1 + R2) + generator (gen-catalog) |
| **SPEC-DRIFT-APPEND-NOT-RECONCILE** | A session appends its harvest to the bottom of a spec WITHOUT reconciling the spec's existing body to the current code — the spec accretes truth at the bottom while stale claims stand above it. | Touching a module = verify its spec still describes what the code does; fix drift the same session. Retiring/renaming any surface triggers a same-commit corpus grep of the retired token across all docs + code comments; each hit triaged (purge / historical-keep / resolve-live). | judgment (+ doc-sync commit trailer) |
| **LIVE-FEATURE-UNDOCUMENTED** | A user-touchable feature ships with no spec section, no registry presence, no user-doc, no acceptance test. It exists only in the session that built it — the next session reinvents or collides with it. | Same commit as the feature: spec section + user-doc at full depth + acceptance test (run GREEN) + registry entry. A design input that shapes a decision but appears nowhere afterward is the same failure. | hook (doc-sync trailer) |
| **STATE-NOT-PERSISTED** | A new user-selectable / persistable variable (enum, toggle, mode, menu pick, numeric control) is added but NOT wired into the save/recall walk — a project/preset recall silently loses the user's choice. A control the user can change but a save can't restore is broken. | Every new persistable state is captured AND restored in the persistence walk IN THE SAME COMMIT (save side + recall side), via a dedicated named field (not buried in a bag). For shared capabilities capture generically via the capability getter/setter so every consumer inherits it. Verify the round-trip: set → save → change → recall → restored. | hook (state-persistence trailer) |
| **PERSISTENCE-HOLE** | The absolute form of the row above, and it earns its own name because it is the one the users feel: ANY state a user can set — bound or unbound, ranged or not, on any surface — that does not re-surface everywhere the thing is reopened, for EVERY consumer (editor · instance · project · library entry · disk) and every user. Persistence is the backbone; a hole in it silently discards work the user did. | Treat the save/recall round-trip as a CORRECTNESS INSTRUMENT, not a feature: it proves the state is wired at all. A batch regression that saves, mutates, recalls and diffs EVERY surface runs as a commit gate on persistence-core files, and it reads a machine-written receipt, never a claim. | gate (persistence walk + full-green batch receipt) |
| **SPEC-WIRED-IN-NAME-ONLY** | A feature/API is specced in docs and shipped in code but has ZERO callers — invisible dead debt that looks done. | At session close, audit every newly-added API and assert at least one consumer exists. An empty caller graph = unwired = not done. | generator (zero-caller orphan report) |
| **DEAD-CODE-SUPERSEDED-NOT-DELETED** | When a shared module supersedes N hand-rolled surfaces, the originals become orphaned dead code that a dedup audit mis-flags as "duplication to extract." Building a shared helper for a zero-caller surface is a fresh SPEC-WIRED-IN-NAME-ONLY violation. | For any "this is built N times" finding: grep for live callers FIRST (exclude the definition, exports, comments). Zero callers ⇒ DELETE, do not extract. A dedup finding is untrusted until grep-confirmed live. | generator + the auditor contract |
| **RETIREMENT-LEAVES-THE-NAME-ALIVE** | A subsystem is purged, but its NAME survives in places the purge never looked: a retired prefix reused by live code "to avoid inventing a new one", a retired id referenced by a doc/test/selector corpus. A purge that greps only the retired subsystem's own files will never find these, and the next reader believes the subsystem is still there. | A retirement sweep greps the retired PREFIX/TOKEN across the WHOLE corpus — code, docs, tests, selectors, generated indexes — not only the retired files. Reusing a dead subsystem's name for a live thing is forbidden: mint identity from an existing generic idiom instead. Measure the blast radius before the sweep, never guess it. | judgment (+ retired-token grep in the doc-sync loop) |
| **REGENERATION-MISSES-EMBEDDED-COPIES** | A corpus-wide regeneration rewrites the source files while SAVED ENTRIES that *embedded* a copy of the old output (a library record, an exported bundle, a cached artifact) keep serving the pre-fix bytes. The corpus looks healed and the user-facing path still serves the bug. | Enumerate every place the output is EMBEDDED, not just where it is generated, and regenerate or invalidate them in the same pass. The acceptance test loads through the USER path (the saved entry), never the freshly generated file. | judgment (+ the user-path acceptance test) |
| **BREAK-WORKING** | The agent modifies working code that wasn't part of the task and breaks it. | Never modify working code unless specifically asked. Anything operator-verified-working is untouchable except through its owning shared path, with test proof before commit. | judgment |
| **NO-GREP-PROOF** | A change is declared complete without a grep audit; a missed reference or parallel path ships broken. | Never ship a spec/code change without the grep audit shown. Audit all parallel paths and list them explicitly. | hook (grep-required) |
| **EDIT-FAILED-BUT-SILENT** | A multi-part refactor (new function + renamed call sites in separate edits) succeeds on one edit and silently no-ops another, leaving call sites pointing at undefined symbols. | After a refactor that spans multiple edits, grep for the new symbol on BOTH sides and smoke-test the path. Never assume both edits landed. | judgment |
| **TROUBLESHOOT-WITHOUT-AUDIT** | The agent debugs a symptom without first checking whether the API/path even has callers — burning a long arc on a feature that was never wired. | Before debugging: grep the caller graph. If only the definition file matches, the API is unwired — that IS the bug. A ten-second grep can answer the whole arc. | judgment |
| **SCOPE-CREEP-SILENT** | One task quietly becomes another; end-state cleanup is compressed and cost is hidden. | Declare scope changes explicitly ("scope change — [list]. Confirm?") and wait. Ripples across files within one focus are fine if declared; a new tangential goal is a scope change. | judgment |
| **GATE-FAILS-OPEN** | A gate, check, or metric reads *absence of signal as presence of correctness* — silence scores as a pass. A verify handed a shape it doesn't understand is silently discarded; an ambiguous lookup returns the first match; an unreadable payload is waved through; a one-sided quality metric ("100% of what shipped is clean") is satisfiable by discarding what it can't handle. A gate that accepts its own known-bad input can never report its own failure, so it is only ever caught sideways. | Every gate and metric must answer "what do I do when I have nothing to say?" — and the answer is never "pass." Unrecognized input is an ERROR, not a skip; ambiguity is an ERROR that names both candidates; an unparseable but plausibly-in-scope payload REFUSES; every quality metric is TWO-SIDED; genuinely-inapplicable is reported SKIPPED explicitly. Prove it: hand each gate the input it must reject and confirm it fails. | meta (self-test corpus + coverage report) |
| **AUTHORED-NOT-PROVEN** | An acceptance test / macro is authored (and cited as a gate in a handoff or commit) without ever having *run*. The commit gates prove tests green *at commit*, but nothing gates the authoring/handoff seam — so a green name ships with no run behind it, and the first real execution surfaces a failure that shipped invisible. | Keep a proven-runs ledger: every green run writes `id → timestamp`. The assembler / lint lists any runnable test absent from the ledger as UNPROVEN, loudly (a strict mode exits non-zero). A handoff or commit may cite a test as a gate ONLY if it is in the ledger. Pair with a hang-guard so a stuck run is a loud red, never silence. | gate (proven-runs ledger + strict lint) |
| **ACCEPTANCE-TEST-BYPASSES-USER-PATH** | An acceptance test drives the system through a path no user has: injecting state directly, minting a fixture, calling an internal loader — instead of the operator-visible flow (open the thing, click the control, read the result). It then passes on a build where the real path is broken end to end, which is the only thing anyone cared about. | Every acceptance test rides the USER path, gesture for gesture, from the surface the user starts on. Internal entry points are for diagnosis, never for the assertion. A test that cannot be expressed as a user path is describing a seam nobody can reach — fix the seam or delete the claim. | judgment (the coordinator audits every brief's acceptance path) |
| **TRAVERSAL-IS-DIAGNOSIS-NOT-VERIFICATION** | A change to one seam is "verified" by driving the whole chain end to end — re-proving every known-good path it happens to touch. The cost compounds silently: every future change pays for every lesson ever learned, until the verification bill is larger than the work. | Build the chain so it can be TRAVERSED the day something breaks; test AT THE SEAM the day you change it. A known-good path is not re-proven because a change rode it; testing resumes on a path when a problem is found on that path. Declare the proof tier per unit of work — the default is ONE comparison — and never run gates over surfaces the diff cannot reach. | gate (proof tier + the label-equals-body check) + **judgment-gate (seam `proofTier`, advisory — it reads the body's MEANING beside the word list, which is the residue an enumeration of instruments can never cover)** + judgment |
| **SYNTHETIC-INPUT-FALSE-POSITIVE** | Interactivity is "verified" by dispatching events from script. Synthetic dispatch targets the element directly and bypasses hit-testing and the real input pipeline, so it succeeds on a surface whose real input path is dead (an overlay swallowing clicks, a pointer-events hole, an unwired listener). Every "clickable, verified" claim made with that instrument is potentially a lie. | Interactivity is proven ONLY by real input through the automation framework's OS-level path. Read-only probes (geometry, state reads) stay allowed. Where the user path opens native chrome (a file dialog), the sanctioned shape is a real click plus the framework answering the dialog — never an in-page fake of the dialog's RESULT, and never a synthetic fallback. | hook (no-synthetic-input) |
| **ONE-SHOT-VERIFY-SAMPLES-TRANSIENT-STATE** | A single-sample probe lands inside a transient window (a rebuild, a re-spec, a reconnect) and reports a red on a healthy path — or a green on a broken one. The flake then costs more than the check ever saved, and teaches the team to distrust the gate. | Liveness- and pixel-grade verification settles on N CONSECUTIVE passing polls before the verdict, never a single sample. Know the transient windows of your own pipeline and assume them. | judgment (harness canon) |
| **POLL-RESETS-APP-DEBOUNCE** | The test runner's settle loop re-fires an idempotent gesture every tick until the condition holds — and thereby resets any app-side debounce longer than the poll interval, forever. The awaited effect lands *after* the runner gives up, so a healthy path times out deterministically and the hunt goes looking in the app. | A settle that re-pokes must know the app's debounce windows: poke once, then wait longer than the longest debounce, or use a non-idempotent settle. When a whole class of tests times out on a path the user can drive by hand, suspect the harness before the app. | judgment (harness canon) |
| **ERROR-REPORTED-AS-NOT-READY** | The system HOLDS a precise, actionable cause (a compiler message, a validation error, a missing asset) and reports a generic readiness state instead — "not ready", "loading", a blank surface. Every debugging session then re-derives what the program already knew. | An error that exists is SURFACED, with its text, at the surface the user is looking at. A readiness state may never stand in for a known cause. Fix it at the shared level (the one place failures are stored and rendered), not per module — and ship an acceptance test that asserts the cause TEXT appears, plus a negative one that asserts it does not when things are fine. | judgment (+ an acceptance test asserting the cause is surfaced) |
| **STALE-MEMORY-AS-CANON** (UNGATED-INPUT-SURFACE) | The enforcement stack gates EDITS and COMMITS, but a session's BELIEFS arrive through input surfaces injected BEFORE any gate: an agent-harness memory store (un-versioned, outside the repo), user-global instruction files, deployed copies of the project's own config. A superseded practice living in one of those overrides current canon, and no hook can fire because no tool call carries the error. | Three layers, all required. **Pin:** a session-start hook states precedence every session — operator > repo canon > hook context > memory; canon-conflicting memory is wrong by definition and is fixed the same turn. **Loop:** memory joins the session-end harvest — superseding a practice updates or deletes the matching memory the SAME session, and the store is mirrored into a versioned twin so drift is diffable. **Handoff contract:** every opener states the start directory, the memory store it keys, and the precedence line. When auditing enforcement coverage, ENUMERATE ALL INPUT SURFACES — a surface with neither a gate nor a pin is where the next bleed happens. | hook (session-start pin) + the harvest loop |
| **PROSE-BRIEF-TO-A-BUILDER** | A build-executing worker is handed the coordinator's SUMMARY of an executable source of truth (the mockup, the schema, the roster, the oracle) instead of the source itself. The builder implements the summary's distillation loss, and no checker can catch it because the checker was pointed at the same summary. | A builder's brief carries PATHS to the executable truth it must read IN FULL, the task as DIFF-AND-IMPLEMENT against those paths, and MECHANICAL acceptance — never a described value, never prose criteria. Where truth exists only as prose, that is a defect to fix first (make it something the system consumes), not a licence to summarize. Prose stays legitimate for routing, context, and judgment framing for agents that produce no code. | judgment (the coordinator audits its own brief) + partially the proof body check + **judgment-gate (seam `briefAudit`, advisory)** |
| **DONE-WITHOUT-A-HASH** | "Ready / done / works" is said about uncommitted, checkpoint-only, or ungated work. No hook gates a sentence, so this is the one hole the stack cannot close mechanically — and it is the one that costs the operator's trust fastest, because they go and test it. | The word is reserved for a NON-checkpoint, full-gate-green commit, CITED BY ITS HASH. A checkpoint is a checkpoint. A partial is not a result: if an arc has a red, a deferral or a remainder, it is not done — keep working or raise the one thing that blocks, never dress a partial in a completion word. | judgment (pinned rule; the cadence + clean-tree gates make the lie pointless) |
| **ESCALATED-A-QUESTION-THE-DOCS-ANSWER** | The agent puts a question to the operator that a spec, roadmap, or prior agent report already answers. It spends the operator's scarcest resource — attention — on retrieval the agent is supposed to do, and it teaches them the docs are decorative. | Search the owning doc FIRST and show the search. An escalation carries what was read, where the gap is, and the options — and only genuinely-new decisions (a ruling, a trade-off, a scope change) reach the operator at all. Ask once, short, after the search. | judgment |
| **SUBSTRATE-LEAKS-INTO-USER-TAXONOMY** | An internal implementation distinction (which backend, which storage class, which rendering substrate) surfaces as a USER-facing category: a separate menu, a separate section, a separate creation flow. Users are made to learn the architecture; every new internal variant then demands its own user surface, forever. | The user taxonomy is the user's mental model; the substrate is an implementation detail carried as metadata on the thing itself. When a new internal variant appears, it joins the EXISTING user category and declares its substrate as a property — never a parallel surface. | judgment (design review) |
| **PER-TYPE-IDENTIFIER-NAMESPACE** | A new type mints its OWN identifier namespace, and shared machinery then recognizes a CAPABILITY by matching that prefix — so the capability belongs to a type instead of to the medium. Every later type re-implements the same capability under its own prefix, and a purge of the first type can never remove the name, because the machinery depends on it. | Capabilities key on the CAPABILITY, never on a type prefix: one namespace for the shared machinery, with the type carried as data. Reject a new per-type namespace at design time — it is legal code, so nothing but review will stop it. | judgment (design review) · a candidate for a judgment seam once a labeled set exists |
| **RULE-LIVES-IN-PROSE-BECAUSE-NO-MATCHER-READS-MEANING** | A standing rule whose signal is MEANING rather than shape can have no executor, so the row sits marked *judgment* and the rule holds only while somebody remembers — which, across a model swap or a long session, means not at all. Examples: "this brief must require its worker to report the retrievals behind its claims", "this paragraph must still describe what the code does", "this body must not describe a whole suite under a light label". Each is satisfiable in a dozen phrasings and violable in a dozen more. MEASURED 2026-09-18: a resident governance paragraph described a hook's behaviour that had changed three days earlier, and every seat reading it reasoned from a sentence already false. ⚠ The INVERSE failure is worse, which is why this row is narrow: a matcher that IS correct gets replaced by a model, and a deterministic verdict becomes a probabilistic one. | Add a JUDGMENT SEAM — a decision model answering ONE closed question at the gate boundary, strictly ADDITIVE to the matcher that already owns that moment (a verdict a regex reaches correctly is NEVER delegated). Code enumerates the options and renders the outcome; the model only picks one, and never writes, counts, orders dates, measures geometry, or judges a render. It ships ADVISORY and PRINTS its engagement state on every pass, so "nothing was asked" is distinguishable from "asked, failed, approved anyway" — the second never happens, because an engaged seam that cannot reach its provider DENIES. Questions live in a versioned roster, never inline in a hook; a band arms only on a TRAINED provider, after a labeled set measures it and a hostile-input leg is green. | hook (judgment-gate — one seam per roster entry; `skills/judgment-SKILL.md`, `governance/LOCAL-MODELS.md`) |

## Frontend module patterns (opt-in — load only when `frontend.enabled`)

These two are CSS/DOM-specific instances of the universal patterns above. A backend
project never encounters them; a web project inherits them when it turns on the
frontend module (`frontend.enabled` in stack.config + the `design-system-export`
skill). Both have generalized siblings in the core table (`NEW-VOCABULARY-WITHOUT-CONSENT`,
`HELPER-HAND-ROLL`).

| Code | What happens | Prevention | Executor |
|------|--------------|-----------|----------|
| **NEW-CLASS-WITHOUT-CONSENT** | The agent invents a new styling class / token / design vocabulary when an existing one would do, forking the design canon module by module. (The CSS instance of `NEW-VOCABULARY-WITHOUT-CONSENT`.) A NAME check alone cannot see the worst case: a class whose *declaration set* already exists under another name passes the "is this name known?" test every time, which is how hundreds of duplicate selectors get born under a rule that was nominally always on. | Every class/token already exists in the canon and is REUSED or DERIVED. A genuinely-new item requires BOTH that it is truly new AND explicit operator consent — then it is written into the canon (registry + spec) in the SAME change. Gate it on three shapes, not one: the NAME (absent from the registry), the DECLARATION SET (already present under another name), and the INLINE BYPASS (a cluster of static style writes that carries no class at all). | hook (new-surface-consent, shapes B/C/D/E) |
| **STRIPPED-SHELL-HOST-MISMATCH** | A standalone/satellite surface (embeddable widget, docs page, portal) reuses design-system classes outside their real host chain — a composed system's classes assume ancestor context (surface tiers, host-keyed flow rules, cumulative offsets), so ONE structural mismatch surfaces as dozens of visual symptoms, each then "fixed" as a styling patch. Hours of grind; the surface forks the design system and still doesn't match. | HOST-FIRST law: the unit of reuse is HOST CHAIN + HELPERS + CLASSES, never classes alone — mount in the REAL host built by the REAL builder functions. Extraction GENERATED from the rendered DOM, never hand-curated. Parity MEASURED (rendered-box comparison, real host vs satellite) with the TWO-MISMATCH tripwire: ≥2 geometry mismatches on one component = HOST problem — stop patching, fix the host. Full method: frontend/design-system-export-SKILL.md. | hook (satellite-gate: manifest + measured-parity trailer) |

## How to add your own patterns (harvest discipline)

A failure pattern earns a row when it (a) is cross-cutting — it can recur in any module — and
(b) has a mechanical prevention. To add one:

1. **Name it in SCREAMING-KEBAB.** The code becomes shared vocabulary in commits, hooks, and
   the §Invariants §Never bucket. Make it self-evident.
2. **Write the row in four parts:** what happens (the failure, generalized — strip project
   specifics), the prevention (the mechanical rule that kills it), and **the executor**.
3. **Decide the executor honestly, and ship it in the same commit.** If the failure is
   detectable at edit, spawn, commit, instrument or turn-boundary time, it becomes a HOOK —
   and the pattern→hook growth gate refuses the row without one, or without an explicit
   `un-gateable (<reason>)`. A row whose executor is "the agent remembers" is not a row; it
   is the story that preceded one.
4. **Ship the hook with its red-fixture.** Hand the new gate the input it must reject and
   watch it block, then hand it a good input and watch it pass. A gate nobody has seen fail
   is an assumption.
5. **Wire it into the §Never bucket** of `CLAUDE.md` in one line.
6. **Harvest at session end.** Any session that surfaces a new cross-cutting failure appends
   the row here AND a one-line note to the project memory — the `@`-import does not
   auto-elevate a buried lesson; only this table does. And say what the new gate RETIRES: a
   stack that only accretes gates ends up charging every change for every lesson ever
   learned.

A pattern that lives only in a session's memory is a story; a pattern in this table is a rail.
